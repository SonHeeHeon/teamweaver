# Phase 0 기본 모델 검증 설계

## 목적

TeamWeaver의 현재 MILP가 설계된 수학 문제를 정확히 풀고, 반환한 해가 모든 제약을 만족하는지 솔버 바깥에서 검증한다. 이 단계는 실제 프로젝트 성과를 예측하거나 현재 가중치가 현실에 맞다고 주장하지 않는다.

## 신뢰 경계

- 검증할 수 있음: 목적함수 구현, 제약식 구현, CBC 해의 실행 가능성, 작은 문제의 전역 최적값 일치, 현재 합성 데이터에서의 실행 시간.
- 조건부로만 말할 수 있음: 합성 데이터와 구조가 비슷한 입력에서의 계산 성능.
- 검증할 수 없음: 추천 팀이 실제 고객 평가나 프로젝트 성과를 높이는지, `lam=0.3`, `mu=0.2`, `slack_penalty=100`이 현실적인지.
- 합성 성과를 현재 목적함수에서 만들어 같은 목적함수를 검증하는 순환 실험은 사업 효과의 증거로 사용하지 않는다.

결과 보고서는 계산 검증과 사업 검증을 분리하고, 후자는 항상 `NOT_CALIBRATED`로 표시한다.

## 범위

이번 구현 주기는 다음만 포함한다.

1. 현재 CBC 기반 MILP의 원시 변수와 상태를 보존하는 진단 실행 경로.
2. 솔버와 독립된 목적함수 재계산 및 제약 검증기.
3. 작은 문제에서 이진 배치를 완전탐색하고 각 배치의 연속 투입률을 SciPy `linprog`로 푸는 독립 정답기.
4. 예산·가용성 단조성 검사, 목적함수 항 크기 기록, pair 절삭 손실 측정.
5. 50명 × 10프로젝트 × seed 42의 설치된 CBC 스모크 실행.
6. 실행마다 갱신되는 원자적 JSON 체크포인트와 초보자용 HTML 결과 보고서.

HiGHS·SCIP 설치 및 300명 × 60프로젝트의 24시간 비교는 이번 범위가 아니다. 실제 인력 데이터 컬럼과 분포가 공유된 뒤 합성 생성기를 조정하고 실행한다.

## 구성요소

### 원시 해 계약

`solve_milp_diagnostic(...)`은 기존 `solve_milp(...)`과 같은 문제를 한 번만 풀고 다음을 반환한다.

- 기존 API가 소비하는 `PlanAssignment`
- PuLP 상태와 원시 목적값
- `z`, `a`, `y`, `slack` 변수값
- 시너지 보상 pair와 과숙련 penalty pair
- 변수·제약 수

기존 `solve_milp(...)`은 진단 함수의 `plan`만 반환해 API 계약을 유지한다.

### 독립 검증기

검증기는 PuLP 제약 객체를 읽지 않고 도메인 입력과 원시 변수만 사용한다. 다음을 다시 계산한다.

- `min_alloc * z <= a <= z`
- 월별 가용성
- 등급별 배치 인원 + 미충원 = 요구 인원
- 프로젝트 월 예산
- `y = z_pj * z_qj` 선형화 결과
- 스킬·시너지·과숙련·미충원 목적함수 항과 합계
- 표시용 `PlanAssignment`가 원시 해에서 안전하게 추출됐는지

위반은 코드, 위치, 실제값, 한계값, 오차를 가진 구조화 항목으로 기록한다. `PlanAssignment.violations == []`는 검증 증거로 사용하지 않는다.

### 작은 문제 정답기

최대 12개의 `person × project` 이진 배치만 허용한다. 모든 `z` 조합을 열거하고 등급 정원과 미충원을 직접 계산한다. 고정된 `z`에서 `y`는 곱으로 결정되며, 연속 변수 `a`만 SciPy `linprog`로 최적화한다. pair 선택도 운영 코드의 `pruned_pairs`를 재사용하지 않고 같은 명세를 독립 구현한다.

CBC 목적값과 정답기 목적값의 절대 차이가 `1e-6` 이하여야 한다. 정답기가 운영 코드를 그대로 호출하지 않으므로 같은 구현 오류를 함께 반복할 가능성을 낮춘다.

## 실험 케이스와 판정 기준

1. 손계산 가능 케이스: 한 프로젝트가 더 높은 스킬 점수의 한 사람을 선택한다.
2. 예산 부족 케이스: 전원 충원이 불가능할 때 예산을 넘지 않고 미충원을 선택한다.
3. 시너지·과숙련 케이스: pair 보상과 penalty가 목적값에 정확히 반영된다.
4. 생성형 소형 케이스: 여러 고정 seed에서 CBC와 정답기가 일치한다.
5. 단조성: 예산 또는 가용성을 늘렸을 때 최적 목적값이 감소하지 않는다.
6. pair 절삭: full-pair 기준으로 다시 평가한 capped 해의 품질 손실을 기록한다.
7. CBC 스모크: 50명 × 10프로젝트 × seed 42를 60초 솔버 제한으로 실행한다.

Phase 0 계산 판정은 다음을 모두 만족해야 `PASS`다.

- 모든 작은 문제에서 CBC와 정답기 목적값 차이 `<= 1e-6`.
- 독립 검증기의 오류 등급 위반 `0건`.
- 모든 단조성 검사 통과.
- 전체 Phase 0 벽시계 시간 `<= 240초`.
- 스모크 실행에 유효 incumbent가 있고 독립 검증을 통과.

목적함수 항 크기와 pair 절삭 손실은 통과 조건을 억지로 맞추지 않고 관측값 그대로 보고한다. 이상값은 다음 모델 설계 논의의 입력이다.

## 체크포인트와 재현성

- 결과 파일: `experiments/results/phase0_model_validation.json`
- HTML 파일: `outputs/phase0-model-validation.html`
- 각 케이스 종료 후 임시 파일을 같은 디렉터리에 쓰고 `os.replace`로 원자 교체한다.
- 기존 실행 결과는 현재 harness 규칙대로 `superseded-N` 파일로 보존한다.
- 환경, Python/PuLP/CBC 버전, 입력 seed, `MilpParams`, 데이터 출처, 각 단계 시간과 실패 원인을 기록한다.
- 실패한 케이스 뒤에도 독립적인 다음 케이스는 실행하고, 전체 상태는 `FAIL`로 남긴다.

## 실제 컬럼 정보가 도착한 뒤

인사 원자료는 받지 않는다. 공유 가능한 컬럼 정의와 익명 분포를 받아 현재 생성기의 필드·결측률·분포·관계 밀도를 조정한다. 과거 프로젝트 성과가 없으면 모델은 계속 정책 기반 최적화로 분류한다. 향후 성과 후보는 고객 평가, 동일 고객의 고도화/후속 과제 발주, 고객 요구 인력 교체, 중도 이탈, 일정·예산 편차, 결함·재작업 등이며, 실제 조직에서 생성·소유·해석되는 방식을 확인한 뒤 별도 설계한다.

## 제외 사항

- 가상의 성과를 근거로 가중치를 학습하거나 정확도를 주장하지 않는다.
- 기존 API 응답 스키마와 웹 UI를 변경하지 않는다.
- 상용 솔버를 설치하거나 비용을 발생시키지 않는다.
- 실제 인사 원자료를 요구하거나 저장하지 않는다.
