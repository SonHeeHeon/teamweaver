   (`org-n100.json` · `org-n100-annual.json` · `org-n100-operating.json` · `org-n100-yearend.json` · `org-n200.json` · `org-n200-operating.json` · `org-n300.json` · `org-n300-operating.json`)을 한 번씩 넣는다(파일당 수 초).
   **2026-10-19에 모두 다시 만들었다** -- 예전에 불러 둔 기록(투입률을 나누던 때의 결과)은 지우고 새로 넣는다.
   배치 설정의 투입 방식이 **전일 투입(100%)**인지 확인한다(예전에 저장한 설정 파일이 있으면 그 값이 남는다).
   "서버가 다시 채점해 기록과 같음을 확인했습니다"가 떠야 한다. 영상 녹화 전에 해 두면 D1·D5·D8에서 **열기**만 누르면 된다.
3. `.env`의 LLM 키 확인(교체 설명·소명 글). 없으면 설명이 규칙 기반으로 나온다 — D3은 "정해진 틀" 글로, D4는 `guard-demo.html`로 대신한다.
4. 브라우저 탭 셋: 슬라이드(`outputs/demo-video-slides.html`), 앱(`http://127.0.0.1:8000`), `rehearsal/results/guard-demo.html`.
5. 시작은 로그인 화면에서 한다(D1). 들어온 뒤 What-if 대시보드가 "아직 볼 편성안이 없습니다" 안내인지 본다 — 기록을 열면 바뀐다.
6. 녹화 순서대로 한 번 미리 눌러 본다. D5·D8에서 데이터를 바꾸므로, 다시 찍을 때는 `org-n100`으로 되돌리고 시작한다.

## 막혔을 때
| 증상 | 대처 |
|---|---|
| 로그인이 안 됨 | 아이디 `admin`, 비밀번호 `admin1234`(서버에 TEAMWEAVER_ADMIN_PASSWORD를 정했으면 그 값). 5번 틀리면 1분 잠긴다 |
| 기록 파일을 받지 않음 | 화면의 이유를 읽는다(파일이 고쳐졌다·형식이 다르다). `demo/records/`의 원본을 다시 불러온다 |
| 계산이 오래 걸림 | 기록을 열었으면 **다시 계산**을 누르지 않은 상태로 진행한다. 급하면 **계산 멈추기** |
| 다시 계산 뒤 기록 결과로 돌아가고 싶다 | 연간 계획에서 **최적화 실행**(같은 설정이면 기록 결과가 다시 나온다), 안 되면 데이터에서 그 기록을 다시 **열기** |
| AI 설명이 규칙 기반으로만 나옴 | LLM 키·네트워크 문제거나, 위반 교체에서 AI가 "보류"를 안 써 버려진 것(측정 20번 중 2번). 다시 누르거나 `guard-demo.html`로 보충 |
| 8000번 포트가 이미 쓰임 | `PORT=8010 scripts/run_poc.sh` |
| PDF 실패 | `cd web && npm run build`, `uv run playwright install chromium` |

## 부록: 현장 시연으로 할 때
영상 순서를 그대로 따르고, 시간이 있으면 두 장면을 끼운다(각 1분).
- **단순 규칙 대비**: What-if 대시보드의 "단순 규칙(기술 1등 우선) 대비" 카드 → **단순 규칙과 비교**(약 1초). 자리당 평균 기술 적합은 단순 규칙이 높다(100명 0.76 대 0.62) — 최적화가 정원에 없는 등급을 예산 안에서 더 넣어 전체 기여를 늘리기 때문이다. 우리 점수표 안의 비교다.
- **"그냥 GPT에게 시키면?"**: `rehearsal/results/llm-vs-solver.html`. 표본이 작다(칸당 2~3회)는 것, 사내 GLM은 잔액 문제로 큰 문제를 못 쟀다는 것을 함께 말한다(`docs/demo-notes.md` 8절).
