- **잘라도 되는 곳**(가이드: 흐름 파악에 지장이 없는 범위의 중간 과정 편집): 파일 고르기 대화 상자, 데이터 전환 대기, 다시 계산 진행, AI 글 대기(소명 약 8초·교체 약 6초), 검토 자료 화면에 들렀다 돌아오는 클릭(D7), PDF 생성 대기. 자를 때는 "(계산 중 일부 생략)"처럼 짧은 자막을 넣는다.

## 막혔을 때
| 증상 | 대처 |
|---|---|
| 로그인이 안 됨 | 아이디 `admin`, 비밀번호 `admin1234`(서버에 TEAMWEAVER_ADMIN_PASSWORD를 정했으면 그 값). 5번 틀리면 1분 잠긴다 |
| 기록 파일을 받지 않음 | 화면의 이유를 읽는다(파일이 고쳐졌다·형식이 다르다). `demo/records/`의 원본을 다시 불러온다 |
| 계산이 오래 걸림 | 기록을 열었으면 **다시 계산**을 누르지 않은 상태로 진행한다. 급하면 **계산 멈추기** |
| 다시 계산 뒤 기록 결과로 돌아가고 싶다 | ① 조건·계산에서 **최적화 실행**(같은 설정이면 기록 결과가 다시 나온다), 안 되면 편성 기록에서 그 기록을 다시 **열기** |
| "안 A로 확정" 창에 "고정을 풀고 확정합니다" 체크가 뜨고 확정이 꺼져 있음 | 연초 6개월 기록(`org-n100.json`)처럼 진행 사업 배치가 고정된 데이터의 기록 안이다(고정을 풀고 짠 안). 체크하면 확정되고 고정이 풀린다. 고정을 지키려면 다시 계산 → "고정 유지하고 짜기". 영상은 연간 백지 기록으로 한다 |
| "AI로 요구 읽기"가 "사전으로 읽은 요구 — AI 키가 없어 …"로 나옴 | `.env`의 LLM 키가 없거나 네트워크 문제 — D7 문장은 사전 별칭·규칙만으로도 같은 요구(Spark·금융 업무·1명·중급)가 나와 그대로 진행해도 숫자가 같다 |
| "기술 이름 정리"의 제안이 "문자열"로만 나옴 | AI 키 문제 — 문자열이 비슷한 8개만 맞는 제안이 나온다. 키를 확인하고 "AI 제안 받기"를 다시 누른다 |
| 긴급 투입·신규 사업 손 편성의 확정 버튼이 꺼지고 "빼 온 자리 n개가 빕니다" | 다른 사업에서 사람을 빼 왔다 — 그 자리마다 "메울 사람 … 넣기"를 누르거나 "메우지 않음"을 체크하고 사유를 적는다(메우지 않으면 그 사업 정원이 줄어 더 이상 빈자리로 세지 않는다) |
| What-if·검토 자료의 "자료 만들기"가 꺼져 있음 | 그 확정 뒤에 다른 확정을 했다 — 자료는 확정이 지금 판일 때만 새로 만든다. 그 장면의 기록을 다시 열고 순서대로 다시 한다 |
| AI 설명이 규칙 기반으로만 나옴 | LLM 키·네트워크 문제거나, 위반 교체에서 AI가 "보류"를 안 써 버려진 것(측정 20번 중 2번). 다시 누르거나 `guard-demo.html`로 보충 |

## 부록: 현장 시연으로 할 때
영상 순서를 그대로 따르고, 시간이 있으면 세 장면을 끼운다(각 1분).
- **단순 규칙 대비**: 편성안 비교·확정의 **단순 규칙 비교** 탭(열면 저절로 계산, 약 1초). 연초 100명 기록에서 자리당 평균 기술 적합은 단순 규칙이 높다(0.76 대 0.62) — 최적화가 정원에 없는 등급을 예산 안에서 더 넣어 전체 기여를 늘리기 때문이다. 우리 점수표 안의 비교다.
- **확정 취소**: 신규 사업 편성의 "지금 팀" 줄 오른쪽 **확정 취소** → 미리 보기(돌릴 것·건너뛸 것) → 취소. 그 확정 하나만 거꾸로 돌린 새 판이 된다(그 뒤 변경은 그대로, 빼 온 사람은 원래 사업으로).
- **"그냥 GPT에게 시키면?"**: `rehearsal/results/llm-vs-solver.html`. 표본이 작다(칸당 2~3회)는 것, 사내 GLM은 잔액 문제로 큰 문제를 못 쟀다는 것을 함께 말한다(`docs/demo-notes.md` 8절).
