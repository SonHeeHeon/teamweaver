## 녹화·편집 안내

- **화면**: 1920×1080, 브라우저 확대 110~125%(표 글자가 영상에서 읽히게), 북마크 막대·알림 끄기. macOS는 `Cmd+Shift+5` 화면 기록. 슬라이드는 전체 화면(`F`)으로 띄운다.
- **녹음**: 화면을 먼저 녹화하고 내레이션을 따로 입히면 구간 길이를 맞추기 쉽다. 그대로 말하며 녹화하면 구간마다 끊어 찍고 이어 붙인다.
- **잘라도 되는 곳**(가이드: 흐름 파악에 지장이 없는 범위의 중간 과정 편집): 파일 고르기 대화 상자, 데이터 전환 대기, 다시 계산 진행, AI 글 대기(소명 약 8초·교체 약 6초), PDF 생성 대기. 자를 때는 "(계산 중 일부 생략)"처럼 짧은 자막을 넣는다.
- **자르지 않는 곳**: 미리 계산 띠, 계산 신뢰도 배지, "참고값 · 재최적화 아님", 오류 6건 목록 — 결과를 어떻게 읽어야 하는지 알려 주는 표시다.
- **길이 점검**: 구간 끝 시각을 큐시트와 맞춘다. 넘치면 D8 → D6 순서로 줄인다(D6은 최선 2명까지만, D8은 기술 지도만).

| "데이터는 모델을 만들기 전에 만들었다" (사실이 아님) | "실제 시스템 형식의 가상 데이터. 성과는 모델과 독립된 숨은 규칙으로 만들었다" |
| 미리 계산을 실시간처럼 | "미리 계산한 결과(같은 데이터·같은 설정)" — 화면 띠와 배지가 같은 말을 한다 |
| 실명·실제 고객명 | 가상 이름, "대형 시중은행 A" |

## 막혔을 때
| 증상 | 대처 |
|---|---|
| 데이터 탭에 "기본 데이터로 시작했다" 경고 | 시연 묶음을 못 읽었다 — 목록에서 다시 고르거나 `run_poc.sh` 재실행 |
| 계산이 오래 걸림 | 데이터 탭 `precomputed.skipped` 확인(설정을 바꿨으면 미리 계산이 버려진다 → 설정 되돌리기). 급하면 **계산 멈추기** |
| 다시 계산 뒤 미리 계산 결과로 돌아가고 싶다 | 요건 설정에서 **최적화 실행** — 같은 데이터·설정이면 미리 계산이 다시 쓰인다 |
| AI 설명이 규칙 기반으로만 나옴 | LLM 키·네트워크 문제거나, 위반 교체에서 AI가 "보류"를 안 써 버려진 것(측정 20번 중 2번). 다시 누르거나 `guard-demo.html`로 보충 |
| 8000번 포트가 이미 쓰임 | `PORT=8010 scripts/run_poc.sh` |
| PDF 실패 | `cd web && npm run build`, `uv run playwright install chromium` |

## 부록: 현장 시연으로 할 때
영상 순서를 그대로 따르고, 시간이 있으면 두 장면을 끼운다(각 1분).
- **단순 규칙 대비**: What-if 대시보드의 "단순 규칙(기술 1등 우선) 대비" 카드 → **단순 규칙과 비교**(약 1초). 자리당 평균 기술 적합은 단순 규칙이 높다(100명 0.76 대 0.62) — 최적화가 정원에 없는 등급을 예산 안에서 더 넣어 전체 기여를 늘리기 때문이다. 우리 점수표 안의 비교다.
- **"그냥 GPT에게 시키면?"**: `rehearsal/results/llm-vs-solver.html`. 표본이 작다(칸당 2~3회)는 것, 사내 GLM은 잔액 문제로 큰 문제를 못 쟀다는 것을 함께 말한다(`docs/demo-notes.md` 8절).
