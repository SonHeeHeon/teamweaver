  "AI 구성 · 사실은 데이터 그대로" 글로 바뀐다(최종 리허설, 외부 AI). 아래는 "근거 사실 83개 · 불리한 사실 10개" 목록 — 글의 밑줄 친 문구를 누르면 해당 사실이 강조된다.
- 글의 흐름: 사업 개요(팀 8명: 박은지·박선우·김하늘·류소윤·최진주·류서현·배선영·이승현) → 요구 기술 충족 → 사람별 배치 근거(경력 개월·레벨·같은 산업 경험) → 함께 일한 기간 →

## 9. 왜 믿을 수 있나 (1분)
- 솔버 답을 원자료로 다시 검사(독립 검증) — 정수성·범위·제약·목적값. HiGHS가 돌려주는 1.0000000000000007 같은 값도 여기서 걸렀다.
- 정답 대조(Phase 0): 작은 사례 11건을 전수 탐색 정답과 비교(갭 0).
- 규칙 결정은 측정으로: "익숙한 쌍" 기준을 세 가지로 비교해 '최근 3년 중 12개월'로 정했다(`rehearsal/results/rule-compare.html`). 협업 보상 쌍 상한 200도 측정으로 정했다(`docs/demo-notes.md` 1절).
- AI 글은 검사기를 통과해야 나간다: 교체 설명은 인용 원문 대조·위반 교체 보류, 소명 글은 사실 목록과 정해진 연결 말.
- 개발 과정: 코드를 바꿀 때마다 독립 리뷰(Codex)를 받고, 지적은 고치기 전 코드에서 실패하는 시험으로 고정했다(최종 점검 2026-10-12에서도 2건을 찾아 고침).

## 10. 한계 (1분)
- 사업 효과는 실제 성과 데이터가 없어 검증 전이다(`NOT_CALIBRATED`). 이 과제에서는 실제 인사 자료를 적재하지 않았다.
  실제로 도입한다면 같은 점검 도구(`core/evaluate/outcome_check.py`)로 "모델 가정이 과거 성과와 맞는지"부터 본다 — 가상 성과로 효과를 입증하는 것은 순환이라 하지 않았다.
- 계수는 설계값이다: 협업 0.3, "오래 붙어 다닌 사이" 감점 0.2(문헌이 두 갈래, `docs/demo-notes.md` 7절), 하위 기술 경력 70% 인정, 경력 개월 → 레벨 경계(12/36/60/96개월).
- 숙련도는 경력 개월로 만든 대리 레벨이라 같은 구간 안의 차이(13개월과 35개월)는 보이지 않는다(`docs/skill-score-decision.md`).
- 운영 기능(직원별 계정·승인 단계·감사·백업)은 시제품 수준이다.
