## 1. 문제와 목표

- 같은 조직 개발자를 여러 실행·제안 프로젝트에 나눠 배치할 때, 기술·협업 이력·월별 가용률·
  등급 정원·월 예산을 함께 계산하고 근거와 대안을 보여주는 의사결정 보조 도구. 최종 결정은 사람이 한다.
- 두 상황을 다룬다: **연초 계획**(백지에서 6개월, 안 A~D)과 **운영 중 편성**(이미 배치된 조직에 신규 제안·보강, 기존 인원은 최대 K명만 이동).
- 모든 데이터는 가상(seed 고정)이고 사업 효과는 `NOT_CALIBRATED`다. 계산이 맞다는 것과 현실 성과가 좋다는 것은 별개 주장이다.
- **범위(사용자 공지 2026-10-12): PoC이자 과제 제출용. 실제 인사 자료는 적재할 수 없고 적재하지 않는다.** 실데이터를 전제로 한 작업(첫 적재 준비·실제 성과 보정·현실 평가·Shadow·파일럿과 운영 준비)은 하지 않고 "실제 도입 시 필요한 것"으로만 적는다.
- LLM은 배치를 정하지 않는다. 쓰는 곳은 세 군데(평가 글 판정·교체 설명·인사팀 소명 글)이고, 모두 기계 검사를 통과한 결과만 쓰며 실패하면 규칙 기반 글로 대신한다.

## 2. 현재 시스템 흐름 (현재 구현)

CSV 묶음(zip, 실제 인사 자료 모양) 또는 시연 묶음 → 검증 리포트(오류 0이어야 활성 데이터셋 교체, 파일·줄·칸까지 표시) →
SQLite 근거 색인 + MemoryGraph(S/C) + 지식 그래프(`core/kg`, 소명 글 사실) → HiGHS MILP(시드 포트폴리오) → 독립 검증 → API → 웹·PDF.

- 입력 계약 `core/ingest/`(사람·단가표·기술 경력 개월·업무 이력·월별 가용 M/M·프로젝트·등급/기술 요구·평가·평가 항목 + manifest, 선택 mapping.json).
  같은 모양의 가상 묶음 생성기(`python -m core.ingest generate|check`, 조직형 100·200·300명). 인사 시스템 실시간 연결은 없다.
- 업로드 자료·적용한 교체·서명 키는 서버 데이터 폴더에 저장돼 재기동 뒤에도 이어진다. 관리자 비밀번호 로그인 하나(직원별 계정·SSO 없음).
- 시연 묶음 6개(100·200·300명 × 연초·운영 중) + 일부러 틀린 묶음. 미리 계산(`demo/precomputed/`)은 데이터 버전(평가 판정값 포함)·설정·평가기 재채점이
  모두 맞을 때만 쓰고, 아니면 조용히 실시간 계산. 평가 글 판정값은 `demo/review_judgments.json`에 동봉.
- API: `/api/meta`, `/api/optimize`(SSE, 안마다 서명 `plan_token`), `/api/whatif`(교체 전후를 MILP 전체 목적·제약으로 재평가한 **참고값** + AI 설명, 새 위반이면 결론 "보류"),
  `/api/plans/apply-swap|apply-alloc`(적용·저장), `/api/report`(서명 확인 뒤 서버가 다시 계산한 PDF), `/api/datasets*`(업로드·되돌리기·시연 고르기·다시 판정),
  `/api/settings`·`/api/admin/*`, `/api/operating/*`(K=0~3 비교 SSE)·`/api/staffing/*`(보강 후보·최선 n명)·`/api/baseline`(단순 규칙 대비), `/api/justification`(소명 글, 서명 필수).
- 실데이터는 외부 LLM으로 보내지 않는다(`api/deps.llm_client_for`: 사내 주소·명시 허용일 때만). 실데이터 평가 원문은 화면·AI 어디에도 내보내지 않고 항목 라벨만 쓴다.

## 3. 모델 (현재 구현)

목적: `Σ S_ij·a_ij + 0.3·Σ C_pq·y_pqj − 0.2·Σ_{익숙한 쌍} y_pqj − 100·Σ slack_jg` 최대화. 계수는 설계값이며 실제 성과로 보정하지 않았다.

| 변수 | 의미 |
|---|---|
| `z[i,j]` | 배치 여부(0/1) |
| `a[i,j]` | 투입률. 배치 시 최소 30%(관리자 설정)~100%, 기본은 사업 기간 내내 같은 비율(달별 투입률은 선택 기능, 기본 꺼짐) |
| `y[p,q,j]` | 두 사람 동시 배치(선형화). **보상 쌍 = \|C\| 상위 최대 200**(10-05, 이전 5,000 — 200명 빈자리 57석·300명 해 없음의 원인), 감점 쌍 = 익숙한 쌍 전부 |
| `slack[j,g]` | 등급 정원 미충원(큰 감점, 출력에 노출) |

- 하드 제약: 월별 Σa ≤ 가용률, 월 예산 Σ(단가·a) ≤ 예산(상대 1e-7 이하 극미세 초과만 보정 LP 후 재검증, C1), 기재 등급별 Σz + slack = 요구 인원,
  **동시 프로젝트 ≤ 3**(관리자 1~6, C6). 운영 중 편성은 이동 예산 K(옮긴 사람은 원래 없던 사업에 들어가야 함)를 더하고 **갭 0**으로 푼다.
- **익숙한 쌍** = 최근 36개월 중 12개월 이상 같은 사업(10-06 사용자 결정, 관리자 설정). 10년 6개월 기준은 실제 같은 이력에서 쌍이 1만 개 안팎이 돼 무너졌다.
- S: 요구 기술별 `min(보유 레벨/요구 레벨, 1)`을 1~5 가중치로 평균. 실데이터에 숙련도 레벨이 없어 **경력 개월 → 대리 레벨**(경계 12/36/60/96개월).
  개월 비율을 직접 쓰는 안은 **채택하지 않음**(사용자 결정 2026-10-12, 근거 `docs/skill-score-decision.md` — 가상 데이터로는 우열을 가릴 수 없고 바꾸는 비용이 큼, 실데이터 성과가 쌓이면 재검토).
  10-09부터 IT 기술 이름 사전(228개)으로 이름을 통일하고 하위 기술 경력의 `0.7^깊이`를 상위 기술에 인정(10-11 사용자 결정 "70% 고정", 이전 0.5, 가정값, `core/ingest/skills.py`).
  인정분이 경력을 정한 기술은 `Person.skill_credit`(출처·인정 개월·본인 개월)로 본인 경력과 구분한다(근거 색인 `skill_credit` 표, 교체 설명 `credited_from`, 화면은 claude-b).
- C: `0.4·min(협업개월/12, 1) + 0.6·평가 점수`. 협업 개월은 최근 10년, 같은 평가자의 여러 회차는 모두 평균, 평가 글 극성은 LLM 판정(10-06 사용자 결정, 실패 시 항목 점수).
- 필수 기술은 하드 제약이 아니고(실데이터 답변 "선호"), 기재되지 않은 등급은 정원식 대상이 아니다(답변 "허용").
- 대안: 이전 플랜과 (사람,사업) 쌍 겹침 ≤80% 컷 + 품질 하한 `alt ≥ A − 0.05·|A|`, 빈 팀·중복·A보다 빈자리 많은 후보 제외(C2). 없으면 "조건을 만족하는 대안 없음".
- 솔버는 HiGHS 고정(PuLP), 같은 모델을 시드 4개 프로세스로 동시에 풀어 최선을 고른다(`TEAMWEAVER_SOLVER_SEEDS`, 관리자 "동시 탐색 수").
  반환 직전 독립 검증기가 원해와 반환 명단을 모두 재계산해야 화면에 나간다. 인원별 권장 시간: 100명 30초·200명 60초·300명 180초.
- 측정하고 채택하지 않은 것(꺼진 선택지로 보존): 자리당 적합도 항, 파트너 다양성 하한(실험 G), 팩터 6종 추가(팩터 실험실).
- 방정식을 다시 쓰는 곳이 다섯(서비스 MILP·벤치 정식·예산 보정 LP·독립 검증기·평가기) — 바꾸면 모두 고치고 Phase 0을 다시 돌린다(`CLAUDE.md` 함정 절).

## 9. 작업 규칙 (이 저장소에서 지켜 온 것)

- 설계(`.omc/plan` 또는 `docs/superpowers/specs`) → 구현 → 자체 검증 → Codex 리뷰(쿼터 소진 시 Claude 폴백 리뷰) → 커밋 → 기록(`handoff-log`).
- 측정은 판정 기준을 **측정 전에 커밋**한다(사전 등록). 결과를 보고 기준·계수·데이터를 맞추지 않고, 실패·중단·미측정도 결과에서 빼지 않는다.
- 테스트의 검출력은 결함을 일부러 주입해 실제로 실패하는지 보고 확인한다.
- 병행 개발: claude-a(`core/ingest`·`core/evaluate`·`core/kg`·`api/rag`) · claude-b(`api`·`web`·`scripts`) · Codex(리뷰 전용). 공유 계약은 work-split "요청"에 먼저 적는다.
- 원격 `origin`(GitHub)이 있다. main 병합은 사용자 승인으로 한다. `private/`(실데이터 답변)·`.omc/`·Phase 1 원시 결과는 Git에 넣지 않는다.
