# 요청: 자료에서 사업 정보 채우기 · 부서장용 자료 요약 — 슬라이드·보고서·D6 대본 (claude-b → claude-a, 2026-10-23)

## 사용자 원문
(입찰공고 자료 — 입찰공고문 `.hwp` + 첨부 묶음 `.zip` — 와 함께)
"사전 규격 번호는 R26BD00208180 이거고, 이후에 입찰 공고 떴을때의 자료도 줄게 이걸로는 기술 및 기술별 필요 역량 이런게 좀 나오는지 봐줘.
그리고 이건 4월 스타트지만 임의로 10월에 올라온 공고로 만들고 시작은 12월에 스타트하는 프로젝트라고 가정하고 신규 사업 편성에 넣어줘.
아니다 시연할 때 아예 내가 이걸 신규 사업 으로 등록 하는게 좋겠다. 여기서 자료에서 메타 정보 따와서 원래 우리가 신규 사업 등록시에 입력했던 프로젝트 이름, 기간, 예산 등을 대신 작성해줄수있나?
물론 사용자가 보고 고칠수 있도록은 만들어 둬야겠지 **이것도 llm의 효과에 들어가야겠지 이건 슬라이드에 들어갈만한거 같은데**
그리고 그 자료들 등록했을 때 그 등록한 프로젝트명을 누르거나 뭐 어디서든 각각의 자료를 llm으로 잘 압축 요약한(이 서비스를 쓰는 부서장입장에서 필요로 하는 정보를 잘 요약해서 보여주기) 걸 각각 보여줄수있는 화면? 팝업? 이 있으면 좋겠어."
결정: 역할 **"이번엔 b가 전부"**(AI 함수도 b) · 예산 = 총액 ÷ 개월 ÷ 1만 원(1점 = 1만 원 가정) · 기간 = 자료의 길이만(시작 달은 양식) · 요약 = 사업명 클릭 → 창.

## 0. 알림 — a 영역에 b의 새 파일
`api/rag/doc_brief.py`(사용자 결정 "이번엔 b가 전부"). `rfp_read`와 같은 원칙·같은 `request_parse._locate`를 쓴다. 고치거나 넘겨받고 싶으면 알려 달라.
- `read_project_meta(text, …)` → 사업명·발주기관·고객 구분·기간 개월·계약기간 원문·총 사업비(원·부가세)·공고번호·제출 마감, 칸마다 근거 말(원문 확인)·금액 다시 읽기, AI 없으면 규칙.
- `summarize_document(text, kind, …)` → 부서장용 요약(한 줄 + 8칸: 사업 개요·주요 과업·기간·일정·예산·계약·인력·역량 요구·평가 방식·유의 사항·산출물), 항목마다 근거 말(150자 안),
  **항목 글의 숫자는 근거 말에 있는 것만**(날짜는 년·월·일 묶음, 시각, 금액, 단위 붙은 수로 비교 · 한글로 쓴 수는 근거 말에 그대로), 전화·이메일·"이름+직급" 꼴 항목 버림, AI 없으면 열쇠말 줄.
  이 검사는 **완전하지 않다**(폴백 리뷰가 찾은 구멍을 막았지만 모든 지어낸 문장을 보장하지 않는다) — 보고서에 "막는다"가 아니라 "거른다"로 써 달라.
- `PROMPT_VERSION`이 저장한 요약의 열쇠다 — 지시문·검사를 바꾸면 올린다.

## 1. 확인 결과 — 입찰공고 자료에도 기술·기술별 역량은 없다 (보고서에 쓸 만함)
- 입찰공고문(산안공고 제2026-68호): 공고명·계약기간("계약체결일로부터 ~ 2026년 11월 13일까지")·사업예산 1억 원(부가세 포함)·제출 마감·평가 기술 70·가격 30·공동수급·하도급 불가 — 기술·인력 요건 없음.
- 제안요청서: 사전규격(R26BD00208180) 첨부와 **글자가 똑같다**. 인력은 평가 "Ⅲ. 세부계획 20점 — 수행원의 전공·연구실적·전문성"과 입찰자가 채우는 투입인력 양식뿐.
- 나머지(용역계약 특수·일반조건, 청렴계약 2편, 개인정보 위탁)는 표준 계약 조건 — 요약이 "부서장이 볼 내용이 적은 자료"로 가른다.
- 그래서 "필요 기술 읽기"는 실제 공공 자료에서 **과업 내용으로 추정**하고 사람이 확인하는 흐름이다(앞 요청 `2026-10-23-rfp-chunked-read.md` 2-1과 같은 결론).

## 2. 슬라이드·보고서 "AI가 바꾼 것"에 두 가지 (사용자 "슬라이드에 들어갈만한거 같은데")
- **자료에서 사업 정보 채우기**: 공고문을 올리고 버튼 → 사업명·고객 구분·기간(개월 → 종료 달)·월 예산(총액 ÷ 개월, 1점 = 1만 원 가정)을 근거 문장과 함께 제안, 사람이 골라 넣고 고친다. 예전엔 사람이 공고문을 보며 손으로 적었다.
- **부서장용 자료 요약**: 등록한 사업명을 누르면 자료마다 요약 — 무슨 일·기간·예산·인력 요구·평가에서 인력 비중·보안·교체 제한 같은 유의 사항. 근거 문장을 원문에서 찾지 못했거나 근거에 없는 숫자를 쓴 항목은 서버가 뺀다(거르는 것이지 완전한 차단은 아님). 한 번 만들면 저장(다시 열면 0원).
- 측정(`scripts/eval_doc_brief.py`, 관문 코드에 고정 → `rehearsal/results/doc-brief.json`): 가상 7편 OpenAI 사업명·개월·월 예산 7/7, 한 번 5.7초(p50)·7편 합계 약 $0.005.
  GLM-5.3-Flash high(보고만) 7/7, p50 8.5초. G4 "검사기 일관성 0건"은 같은 검사기로 다시 잰 **자기 검증**이라 환각이 없다는 근거로 쓰지 않는다(폴백 리뷰).
  **가상 자료는 표가 정돈돼 규칙만으로도 7/7** — AI의 몫은 실제 자료에서 드러난다:
  실제 공고문은 기간이 "계약체결일 ~ 11월 13일"뿐인데 AI가 7개월로 셈(규칙은 못 함), KISDI 제안요청서는 "사업명:" 표지가 없어 규칙은 사업명을 못 찾고 AI는 찾음.
  계약 조건·청렴계약 문서는 AI가 "덜 중요(low)"로 가름.
- 원칙(이미 쓰는 문장과 같다): AI는 자료 글자만 받고(사람 정보 없음), 결과는 제안, 결정은 사람. 서버가 근거로 확인하지 못한 값(AI가 날짜로 센 기간, 규칙으로만 찾은 값)은
  "AI 계산"·"규칙" 표시와 "확인 필요"로 보이고 미리 체크하지 않는다.

## 3. D6 시연 대본 (`docs/demo-script.md` — 앞 요청의 3절을 이것으로 바꿔 달라)
- 출처: 한국산업안전보건공단 「생성형 AI 기반 산업안전보건 비정형 데이터 정제·구조화 및 활용체계 구축 연구 용역」 — **사전규격 R26BD00208180 → 입찰공고 산안공고 제2026-68호**.
- **가정(사용자)**: 실제는 2026년 4월 공고지만 시연은 "10월에 올라온 공고, 12월 시작"으로 본다 — 그래서 양식의 시작 달을 2026-12로 두고, 자료에서는 기간의 **길이(7개월)**만 가져온다.
  연말형 데이터의 계획 기간은 2026-10~2027-03이라 2027-04~06은 계산에서 잘린다(등록은 된다).
- 장면(화면에서 실측, 2026-10-23):
  1. 신규 사업 등록 → ① 시작 달 2026-12 → 발주 자료 두 개: 입찰공고문 `.hwp`(종류 **입찰공고문** — 새 종류) + 제안요청서 `.hwp`(종류 제안요청서(RFP)).
  2. "자료에서 사업 정보 채우기(AI)" → 약 5~6초 → 사업명·**대외공공**(체크됨) + **7개월 → 2026-12 ~ 2027-06**·**월 1,429점**(= 1억 원 ÷ 7개월, 1점 = 1만 원) —
     공고문엔 개월 수가 없어 AI가 날짜로 센 값이라 **"AI 계산 · 확인 필요"로 체크가 비어 있다** → 근거("계약체결일로부터 ~ 2026년 11월 13일까지")를 보고 사람이 체크 →
     참고로 발주기관·공고번호·제출 마감 → "고른 4개 칸에 넣기". (말할 거리: "AI가 계산한 값은 사람이 확인하고 넣는다")
  3. ④ 필요 기술 → 읽을 자료 **제안요청서** → 약 9초 → "읽은 부분에서 기술별 경력·인원을 찾지 못해 … 추정" 안내 → "추정 n개 모두 선택" → 넣기 → 등록.
  4. 신규 사업 제목(사업명)을 누르면 **자료 요약** 창 → 입찰공고문 탭 "AI로 요약 만들기"(약 9초) → 제안요청서 탭(약 14초, 근거를 확인 못 한 항목 n개를 뺐다는 표시) → 닫고 다시 열면 바로(저장).
- **말할 문장(사용자 지시, 앞 요청과 같음)**: "민간 기업의 RFI·RFP는 초청한 업체에만 보내는 비공개(비밀유지) 문서라 구할 수 없어, 시연·검증은 나라장터에 공개된 공공 자료로 진행했습니다."
- 파일은 저장소에 없다(실제 기관 문서) — 시연자가 화면에서 올린다. 공고문에 공무원 실명·전화가 있어 전화·이메일·"이름+직급" 꼴이 든 요약 항목은 버린다(이름만 따로 쓴 경우까지 모두 잡지는 못한다).
