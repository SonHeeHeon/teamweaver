## 바라는 것 (a)
1. **읽기 함수**(`api/rag/` 새 파일, 이름은 a 판단). "상황을 말로"(`api/rag/request_parse`)와 같은 원칙이다:
   - AI는 **사전 개념 id 안에서만** 고른다.
   - 근거 말(quote)이 원문에 있어야 받는다(위치는 서버가 다시 잰다).
   - 사람 정보는 AI에 보내지 않는다(자료 글자만).
   - AI가 없거나 실패하면 규칙(사전 별칭 찾기)으로 돈다.
   - 제안하는 모양(바꿔도 된다, 확정되면 이 문서에 적어 줄 것):
     ```python
     read_requirements(text: str, sd: SkillDictionary, *, client, model: str | None = None) -> dict
     # {"skills": [{"concept_id", "name"(대표 이름), "months": int | None, "headcount": int | None,
     #             "quote": str, "start": int, "end": int, "kind": "required" | "preferred"}],
     #  "unmapped_terms": [str], "method": "ai" | "rule", "model": str | None, "warnings": [str]}
     ```
   - 범위: 경력 개월 0~240, 인원 1~10.
   - 우대(preferred)와 필수를 가를 수 있으면 가른다. 화면은 필수만 기본 체크한다.
   - 기존 시스템 설명("현재 Oracle 운영")처럼 요구가 아닌 기술 언급은 빼는 것이 핵심 난점이다.
2. **사전 등록 측정**: OpenAI(서비스 모델 gpt-6-luna)와 사내 대리 GLM-5.3-Flash를 **각각** 잰다(사용자 "각각 성능 확인 필요"). 규칙(AI 없이)이 기준선이다.
   - 정답 세트: 위 시연 자료 7개(쉬움) + **어려운 가상 자료**. 어려운 자료에는 다음을 넣는다:
     - 별칭·한글 표기(쿠버네티스, 스파크)
     - 문장 속 요구("대용량 배치 처리 경험 5년 이상 2명")
     - 요구가 아닌 기술 언급(현행 시스템·연계 대상)
     - 우대 사항
     - 표 없는 공공 RFP 문체
   - 지표: 기술 정밀도·재현율, 경력 개월 일치(±12), 인원 일치, 한 편 시간 p50, 비용.
   - 실데이터 원칙: 민간 RFP는 비밀유지 대상일 수 있다. 실제 도입에서는 사내 LLM 경로가 기본이 되어야 한다.
     - 보고서에는 "실제 도입 시"로만 적는다.
     - 가상 자료만 외부 AI로 보낸다(기존 `TEAMWEAVER_REVIEW_ALLOW_EXTERNAL` 규칙과 같은 판단).
3. **보고서·대본**: 보고서 3.3 "AI가 바꾼 것"에 한 줄 추가(전: 부서장이 RFP를 읽고 기술을 하나씩 고름 → 후: 자료를 올리면 후보 기술을 근거와 함께 채움, 사람이 확인·수정). 시연 D6 신규 사업 등록 장면에 자료 올리기 → 읽기 → 고치기.
