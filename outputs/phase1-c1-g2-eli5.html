인력 추천 결과, 원본부터 최종 판정까지 남깁니다

C1 · G2 벤치마크 연결 체크포인트 · 2026-10-04

왜 이 작업이 필요한가요?

솔버는 수학적 조건에 맞는 인력 구성을 찾는 계산 프로그램입니다. 계산 프로그램이 “찾았다”고 말해도 우리 서비스의 별도 검사에서 예산 초과 등이 발견될 수 있습니다. 이전 실험에서는 이런 거절의 원본 숫자를 충분히 남기지 못했습니다. 이제 결과뿐 아니라 원본과 검사표를 같이 보관합니다.

이 단계는 실험용 연결입니다. 서비스 코드의 기존 C0 회귀 6개를 해결했다는 뜻이 아닙니다. 모든 인력과 점수는 합성이며 현실 성과는 NOT_CALIBRATED, 즉 실제 효과가 검증되지 않은 상태입니다.

어떻게 동작하나요?

순서쉽게 설명하면기록
1. 원본계산 프로그램이 내놓은 숫자를 그대로 찍습니다.native-candidate.json
2. 기존 정리기존 어댑터의 경계값 정리를 한 값도 따로 보관합니다. 원본 검사와 구분합니다.validation-candidate.json
3. 제한 보정예산만 극미세하게 넘었고 정수 인원 선택이 정확할 때, 인원은 바꾸지 않고 투입률만 최대 0.0000001 움직입니다.candidate-assessment.json
4. 최종 검사원래 엄격한 기준으로 다시 검사합니다. 통과한 결과만 최종 파일을 만듭니다.raw-solution.json

검사 허용오차는 0.000001 그대로입니다. 보정은 최대 2초의 추가 계산 예산 안에서 수행하며, 실험 워커의 전체 마감시간 밖으로 연장하지 않습니다. 잘못된 정수 선택이나 큰 위반은 보정 대상이 아닙니다.

무엇을 바꿨나요?

CBC·HiGHS·SCIP 모두 같은 보정·검사 정책을 사용합니다. 실행 명세에는 정책의 모든 임계값과 지문을 적습니다. 지문은 파일이나 설정이 바뀌었는지 확인하는 요약 번호입니다. 과거 명세에 정책이 없으면 새 정책으로 몰래 재개하지 않습니다. 과거 결과를 읽는 것은 계속 가능합니다.

결과 파일에서 원본 파일들의 위치와 지문을 묶어 저장합니다. 보고서는 해당 파일이 실행 폴더 밖을 가리키거나 내용이 바뀌면 거절합니다. 숫자가 NaN처럼 유효하지 않을 때도 JSON을 깨뜨리지 않고 명시적 오류 태그로 남깁니다. 저장 실패는 성공이 아닙니다.

좋은 점수와 검증 통과는 다릅니다

실행 완료, 제약 통과, 품질 통과, 원본 통과를 각각 셉니다. 품질은 현재 점수와 솔버가 제공한 상한의 간격으로 판단합니다. 상한을 모르면 BOUND_UNKNOWN, 상한이 현재 점수보다 낮아 모순되면 BOUND_INVALID입니다. 보정한 결과에는 “최적임이 증명됨” 표시를 붙이지 않습니다. 상한이 있다고 무조건 신뢰해서도 안 됩니다.

검증과 한계

관련 61개와 전체 Phase 1 테스트 222개가 통과했습니다. 최고 역량 모델의 독립 리뷰도 G2 PASS입니다. 원본과 정리 결과의 분리, 파일 변조 거절, 정책 변경 거절, 상한 미상·모순, 보정 후 최적 증명 금지를 검사했습니다. 세 가지 리뷰 발견 사항은 실패를 재현하는 테스트를 먼저 작성하고 수정했습니다. 자세한 증거는 G2 리뷰 기록에 남깁니다.

파일 지문은 우발적 변경을 찾는 장치이지 서명이나 외부 공증이 아닙니다. 원본이 없던 과거 87개 거절을 이번 보정으로 해결했다고 다시 계산하지 않습니다. HTML은 정적 구조·보안 검사 대상이며, 이 환경의 로컬 파일 브라우저 접근 제한으로 실제 화면 검수는 수행하지 않았습니다.

다음은 무엇인가요?

최고 역량 독립 리뷰에서 G2가 통과하면 같은 정책을 서비스 경로에 연결합니다. 기존 실패 6개는 수정하거나 제외하지 않고 그대로 재검증하고, 추가 제약과 실제 기본 부팅까지 확인합니다. 이후 새 실행 번호로 소형 3솔버 비교를 합니다. main 병합과 원격 push는 별도 사용자 승인 전 수행하지 않습니다.

이 HTML과 코드는 로컬 기능 브랜치의 체크포인트로 보관합니다. 원격 주소는 있지만 push 승인 전에는 원격에서 내려받을 수 있다고 주장하지 않습니다.
