먼저 읽을 것: 모든 데이터는 가상(seed 고정)이다. 여기의 숫자는 계산이 맞는지와 설계한 점수표 안에서 얼마나 좋은지를 보여 줄 뿐, 실제 사업 성과가 좋아진다는 증거가 아니다(NOT_CALIBRATED). 계수(협업 0.3·익숙함 감점 0.2·하위 기술 인정 70% 등)는 설계 가정값이다.

1. 한 줄 요약

기술 적합도·협업 이력·월별 가용률·등급 정원·월 예산을 한 번에 계산해 배치 안 A~D를 내고, 운영 중에는 "몇 명만 옮기면 얼마나 좋아지나"를 보여 주며, 교체 검토·인사팀 소명 글·PDF까지 근거와 함께 내는 도구를 만들었다. 배치 결정은 수학 최적화(솔버)가 하고, AI는 글(평가 판정·교체 설명·소명)만 쓴다 — AI 글은 모두 기계 검사를 통과해야 나가고, 실패하면 정해진 틀의 글로 대신한다.

2. 무엇을 만들었나

기능무엇을 하나근거·검증
연초 계획(안 A~D)백지에서 6개월 배치. HiGHS 혼합정수계획(시드 4개 동시 탐색), 대안은 구성이 다르고 품질이 A의 95% 이상만반환 직전 독립 검증기가 원해·반환 명단을 다시 계산(통과한 것만 화면에)
운영 중 편성이미 배치된 조직에 신규 제안·보강. 기존 인원은 최대 K명(0~3)만 이동, K별 개선을 하나씩 바로 표시. 사업 보강 후보·최선 n명, 결과에서 이어서 보강, 서명된 결과 PDF갭 0으로 풀어 "최선 증명" 표시
교체 검토(What-if)"A 대신 B를 넣으면?" — 전체 점수·제약으로 다시 평가(참고값) + AI 설명. 새 위반이 생기면 결론은 "보류"AI 인용은 원문과 대조, 규칙 어기면 버리고 규칙 기반 설명
인사팀 소명 글지식 그래프 사실로 "왜 이 팀인가"를 씀(GraphRAG). 근거 문구를 누르면 근거 사실 강조, 불리한 사실 표시, AI가 빠뜨린 불리한 사실은 서버가 사람별로 덧붙임서버 계산 명단(서명)만, AI 원문·탈락 문장은 내보내지 않음
조직 기술 지도기술별 실무 가능 인원·숙련자·비어 있는 사람·요구 사업·신규 제안 부족·희소 기술하위 기술에서 인정받은 경력은 구분 표시
데이터·설정실제 인사 자료 모양의 CSV 묶음 업로드(오류를 파일·줄·칸까지), 시연 묶음 6개, 관리자 설정(최소 투입률·익숙한 쌍 기준·동시 프로젝트·계산 시간·동시 탐색 수)업로드·교체·서명 키는 재기동 뒤에도 유지
PDF배치 명단·지표·교체 이력·소명 글(선택)서버가 서명을 확인하고 명단을 다시 계산해 찍음

3. 계산이 맞고 쓸 만한가 (외부 AI 운영 기준)

  • 정답 대조(Phase 0): 작은 문제 7건은 모든 배치를 하나하나 따져 본 정답과 모두 일치(gap 0). 여기에 예산·가용률을 늘리면 점수가 줄지 않는지(2건), 보상 쌍 상한 실험, 작은 실행 점검을 더해 11/11 통과. 모델을 바꿀 때마다 다시 돌린다.
  • 솔버 비교(Phase 1): 같은 입력 357칸에서 HiGHS가 가장 안정적 → 서비스 솔버로 고정. 보상 쌍 200·최근 3년 익숙한 쌍 규칙·시드 4로, 지금 시연 데이터(10-11 미리 계산)의 연초 계획은 100·200·300명 모두 안 A~D 빈자리 0(300명 안 A~D 약 9.6분). 12개 안 중 9개는 시간 한도에서 멈춘 해라 최선이 증명되지 않았다(화면에 "최적값이 최대 몇 % 높을 수 있음"으로 표시).
  • 운영 중 편성(100명, 90명 배치·대기 10·신규 2): K=0~3 빈자리 2→1→0→0, 배치 품질 67.86→68.59→68.37→69.13(K=2는 빈자리를 메우느라 품질이 조금 내려가도 총점은 오른다), 모두 최선 증명.
  • 단순 규칙 대비(점수 높은 사람부터 채우기): 배치 품질 100명 31.7 → 57.6, 300명 113.2 → 166.1(시연 대본 화면 값) — 우리 점수표 안의 비교다. 자리당 평균 기술 적합은 단순 규칙이 더 높다(100명 0.76 대 0.62) — 최적화가 정원에 없는 등급을 예산 안에서 더 넣기 때문이다.
  • AI가 배치를 직접 하면(E6): 외부 AI는 20명에서 솔버의 89~94%. 100명에서는 원자료만 주면 쓸 수 있는 배치 0/2(규칙 위반·빈자리), 우리 점수를 주고 한 번 고치게 해도 2/3 성공에 품질은 솔버의 55%·약 6분(솔버 30초). 칸마다 2~3회라 표본이 작다. → 배치 결정은 솔버가 한다.
  • 평가 글 판정(외부 gpt-6-luna low): 정답이 있는 글 300건에서 실제 부정 리뷰를 89% 잡음(정답과 상관 0.94). 새 시연 글(생성기 v2) 300건에서는 직설형·"항목보다 독한" 글을 모두 부정, "항목보다 부드러운" 글을 긍정으로 읽어 항목이 아니라 글을 따랐다.
  • 교체 설명(외부): 100건 중 93% 바로 사용, 새 위반 교체의 "보류" 준수 90% — 지키지 않은 7건은 서버가 버리고 규칙 기반 설명으로 대신했다. 10-12에 지시문을 강화한 뒤 화면과 같은 입력으로 다시 재니 위반 교체의 "보류" 첫 문장 18/20, 인정 경력 출처 괄호 표기 9/10(빠뜨리면 서버가 한 문장 덧붙임).
  • 소명 글(외부): 채택 99.4%·처음 보는 데이터 99.6%, 일부러 넣은 오류 13,323개를 모두 걸러냄, 한 편 약 8초·$0.0009.

4. 사내 모델로 바꾸면 무엇이 달라지나

사내 서버로는 잴 수 없어 Z.ai 공식 API의 GLM-5.3-Flash를 사내 LLM으로 가정했다(이전에는 GLM 5.3, 너무 비싸 10-11 교체). 서비스는 외부 AI로 운영하기로 했다(사용자 결정 2026-10-11). 아래는 같은 입력·같은 지시문으로 바꿔 끼웠을 때의 차이다.

5. 판단이 갈렸던 곳(사용자 결정)

  • 평가 글 판정은 선택지 없이 LLM으로(10-06) — 규칙 기반은 글을 읽지 않았다(E4: Jev 판정기는 부정 17%).
  • 익숙한 쌍 = 최근 3년 중 12개월(10-06) — 10년 6개월 기준은 200·300명에서 풀이가 무너졌다.
  • 인사팀 소명은 GraphRAG(10-09, 사용성), AI가 빠뜨린 불리한 사실은 서버가 덧붙임(10-10), 사람별 줄(10-11).
  • 사내 LLM = Z.ai GLM 가정(10-07) → GLM-5.3-Flash로 교체(10-11, 예산), 서비스는 외부 AI 운영·사내 차이는 이 보고에(10-11).
  • 하위 기술 부분 인정 70% 고정·인정 경력 구분 표시, 근거 번호 대신 근거 문구, 가상 데이터는 가상 이름(10-11).
  • 채택하지 않은 실험: 자리당 적합도 항, 파트너 다양성 하한, 추가 팩터 6종(측정 후 기각, 꺼진 선택지로 보존).

6. 한계

  • 사업 효과는 검증되지 않았다(NOT_CALIBRATED). 과거 성과(가상)로 본 협업 보상 방향은 다변량에서 견고하지 않고, 익숙함 감점은 판단할 표본이 부족했다. 가상 성과로 효과를 입증하는 것은 순환 검증이라 하지 않았다.
  • 실제 인사 자료로 돌려 본 적이 없다(입력 계약·검증 리포트·가상 묶음까지). 숙련도는 경력 개월에서 만든 대리 레벨이다.
  • 시연 평가 글은 생성기가 쓴 가상 글이다(v2: 아쉬운 점을 항목마다, 직설형 평가자 8%, 항목과 온도가 어긋난 글 5%).
  • 운영 기능(직원별 계정·승인 단계·감사·백업·배포·모니터링)은 시제품 수준이다 — 관리자 비밀번호 하나, 단일 서버 프로세스.

7. 다음 단계(제안)

  1. 실제 인사 자료 첫 적재: 사람 ID 형식·칸 이름 매핑·사전에 없는 기술 이름 확인, 평가 글 판정 위치(사내 주소·동의).
  2. 점수 계약 정리: 대리 레벨 대신 경력 개월 비율(공유 계약, Phase 0 동반). 데이터셋 버전에 기술 사전 버전·인정 비율 넣기(만들어 두었으나 시연 미리 계산을 무효로 만들어 다음 재계산 때 함께 넣기로 미룸).
  3. 현실 평가 → 섀도 모드(사람 결정과 나란히) → 제한 파일럿: 승인된 과거 성과(고객 평가·교체 요청·후속 과제)로만 효과를 본다.
  4. 운영 준비(파일럿 시): 계정·권한, 승인·원장, 감사, 백업·배포·모니터링, 작업 큐.
