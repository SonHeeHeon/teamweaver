중복 배정 거절

같은 사람을 같은 프로젝트에 두 번 적으면 거절합니다. 사전 검사에서 중복이 사전(dictionary)에 합쳐져 사라지던 문제를 막았습니다.

변경: core/optimize/milp.py, core/optimize/validation.py, 관련 테스트. 목적식 4항과 계수·쌍 선택 함수는 유지했습니다. 검증은 현행 기본 모델 계약을 기준으로 합니다. 표시 배정의 독립적인 제약 검증과 반올림 수정(C3), 추가 다양성 제약 검증(C2)은 남아 있습니다.

05

왜 전체 테스트가 아직 실패하나요?

기존 테스트의 seed 2에서 예산 2046에 대해 원시 합계가 2046.0000025였습니다. 기본 동결 데모에서도 예산 잔차 0.000002~0.0000025가 나왔습니다. 작은 차이지만 현행 허용오차 0.000001보다 커서 차단됩니다.

정상 API 부팅은 기본 계획을 미리 계산하는데, 이 검사에 실패해 부팅도 막힙니다. 즉, 안전 동작은 확인했지만 서비스 가동 호환성은 아직 해결되지 않았습니다. 화폐 단위와 허용오차·솔버 출력 정밀도를 다루는 C1에서 원인을 분석하고 정책을 정해야 합니다.

원시 초과를 실제 비용 초과라고 단정하지 않습니다. 입력은 합성이고 비용 단위 정책이 아직 확정되지 않았습니다. 계산 결과를 임의 수정하거나 검사 기준을 완화하지 않았습니다.

독립 리뷰와 기록

최고 역량 모델 GPT-6-astra가 구현자와 독립적으로 코드·테스트·부팅 경로를 검토했습니다. C0 안전 동작과 소유 영역 준수는 PASS, 전체 회귀와 병합 준비 상태는 FAIL로 판정했습니다. 기본 데모 부팅 거절도 직접 재현했습니다.

보완 요청이었던 “A안 뒤의 잘못된 대안 차단”과 작은 예산 잔차 거절 테스트를 추가했습니다. 심각한 미검증 후보 반환 우회는 발견되지 않았지만, 전체 가동 준비가 끝났다는 뜻은 아닙니다.
