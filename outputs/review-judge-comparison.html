리뷰 글 판정기 비교: 외부 LLM · 사내 LLM · Jev

실험 E4 · 코드 experiments/jev/e4_judges.py · 원시 결과 experiments/jev/results/e4_*.json · 모든 데이터는 가상(합성)이며 사업 효과는 NOT_CALIBRATED

결정(사용자, 2026-10-06): 리뷰 글 판정은 선택지 없이 LLM(OpenAI 호환 API)으로 통일한다. 사내 온프렘 LLM은 주소(TEAMWEAVER_REVIEW_BASE_URL)·모델(TEAMWEAVER_REVIEW_MODEL)만 바꿔 같은 방식으로 쓴다. LLM을 쓰는 곳의 비교는 외부 AI(gpt-6-luna)와 회사가 제공하는 오픈소스 LLM(GLM 5.3)을 항상 함께 잰다.

1. 왜 비교했나

협업 점수의 리뷰 부분은 쌍 리뷰 점수 = 0.5 × 항목 점수 + 0.5 × 글 점수다. 이전 기본이던 규칙 기반은 글 점수 자리에 항목 균형을 다시 넣어, 평가 사유(글)를 점수에 전혀 쓰지 않았다(항목을 두 번 씀). 글을 읽는 판정기 후보로 외부 LLM(gpt-6-luna), 사내 LLM(GLM 5.3), 판단 전용 모델 Jev를 같은 글로 비교했다.

2. 방법

  • A. 시연 원문 — 시연 묶음 100명의 리뷰 1,372건 중 모든 판정기가 판정한 480건(파일 앞쪽에서 판정된 것 — 무작위 표본 아님, API 잔액 소진으로 중단). 생성기가 아쉬운 점을 한 줄로 몰아 쓰고 부드럽게 써서, 글이 항목만큼 부정적이지 않다. 정답이 없으므로 분포만 본다.
  • B. 충실한 글 — 같은 리뷰에서 300건을 뽑아, 고른 항목을 빠짐없이 한 문장씩 다시 쓴 글. 글이 항목을 그대로 담으므로 정답 = 항목 균형((좋은 점 수 − 아쉬운 점 수) ÷ 전체 항목 수).
  • 대조 문장 — 명백한 부정·긍정 등 4건으로 척도(−1~+1)가 살아 있는지 확인.
  • 두 LLM은 같은 지시문(서비스 파서, "서술 전체의 감성 강도", −1~1 JSON)을 받는다. GLM 5.3은 회사 밖인 여기서 Z.ai 공식 API(glm-5.3, 추론 강도 max — 사용자 지정)로 쟀다. Jev는 5단계 점수의 확률 기댓값을 −1~1로 옮겼다. 부호 판정의 중립 구간은 ±0.1. 모두 병렬 16건 동시 호출.
부분 결과

5. 해석

  • 순위는 셋 다 잘 맞힌다(B 상관: 외부 +0.94, 사내 +0.94, Jev +0.94). 차이는 부정 검출이다: 외부 LLM 92%, 사내 GLM 84%, Jev 17%. Jev는 "조금 아쉬웠습니다"처럼 부드럽게 쓴 지적을 긍정으로 읽는다.
  • 외부 AI 대 사내 AI: 부호 일치 84% 대 82%, 평균 절대 차이 0.20 대 0.20, 건당 지연 중앙값 2.1초 대 10.5초(GLM은 추론 max라 답 전에 생각 토큰을 쓴다).
    두 LLM의 차이는 이 표본에서 통계적으로 확정되지 않는다: 실제 부정 리뷰 83건 중 한쪽만 맞힌 건이 외부 7건·사내 1건(McNemar 정확검정 p≈0.07), 부정 검출 95% 구간 외부 84~96%·사내 75~91%가 겹친다. 부호 일치도 한쪽만 맞힌 건 10건 대 5건(p≈0.30). Jev와의 차이는 뚜렷하다.
  • A에서는 모든 판정기가 긍정으로 쏠렸다. 판정기 문제가 아니라 시연 생성기의 글이 항목보다 부드럽기 때문이다 (아쉬운 점을 한 줄로 몰아 쓰고, 모든 리뷰가 칭찬 문장으로 시작). 생성기 수정은 데이터 담당(claude-a)에 요청했다.

6. 한계

  • 결정 근거(부정 검출)는 B(생성기 문장으로 다시 쓴 글)의 결과다. 시연 원문(A)에서는 모든 판정기가 부정을 거의 못 잡았다 (외부 3% · 사내 4% · Jev 0%). 그래서 LLM 판정은 지금 시연 데이터의 리뷰 점수를 긍정 쪽으로 옮긴다(평균 외부 +0.59 · 사내 +0.58 대 항목 균형 +0.15). 배치 결과에 주는 영향은 재지 않았다.
  • 정답은 "항목 균형"이다. 이것은 글을 만든 의도이지 실제 협업 성과가 아니다(NOT_CALIBRATED).
  • B의 글은 생성기의 문장 은행으로 만들었다. 실제 사람의 글(직설적인 평가 포함)과는 표현 폭이 다르다.
  • 사내 GLM 5.3 결과는 Z.ai 공식 API로 잰 대리값이다. 같은 공개 가중치지만 사내 서빙(BF16/FP8, vLLM 버전, 추론 설정)이 다르면 결과·속도가 달라질 수 있다. 사내 엔드포인트에서 E4_TAG=onprem TEAMWEAVER_REVIEW_BASE_URL=… TEAMWEAVER_REVIEW_MODEL=…로 다시 재면 실제 값이 나온다.
  • 이전 실험 E2(가상 fixture 266건, outputs/jev-experiment.html)에서도 같은 방향(LLM 부호 일치 74% 대 Jev 61%)이었다.
