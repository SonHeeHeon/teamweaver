두 개의 안전망

좋은 결과는 “만들기”만으로 끝나지 않습니다. 최고의 검토와 쉬운 설명이 함께 있어야, 다음 사람이 결과를 믿고 이어갈 수 있습니다.

① 작업
설계·코드·분석
② 가장 강한
모델로 검토
③ ELI5 HTML
쉽게 설명
④ Git 기록
다운로드 준비
1

왜 규칙이 필요한가?

같은 결과라도 검토의 깊이가 들쭉날쭉하거나 설명이 너무 어렵다면, “정말 맞는가?”를 나중에 알기 어렵습니다. 그래서 품질 확인과 전달 방식을 작업 절차에 넣었습니다.

2

검토에는 가장 강한 모델

설계, 코드, 테스트, 결과 해석, 최종 병합 전 점검까지 그때 사용할 수 있는 최고 성능 모델로 따로 검토합니다. 구현한 모델과 검토 모델을 가능하면 분리해, 자기 답을 자기만 믿는 일을 줄입니다.

만든 결과
독립 검토
근거 확인
통과 또는 수정
3

최고 모델을 못 쓰면 숨기지 않기

일시적으로 최고 모델을 사용할 수 없으면, 그다음으로 강한 모델을 쓰되 이유와 남는 위험을 검토 기록에 남깁니다. “검토했다”라는 말만 남기지 않고, 무엇을 확인했는지 근거도 적습니다.

4

작업 끝에는 누구나 읽는 HTML

설계·구현·디버깅·검증처럼 의미 있는 작업 하나가 끝날 때마다 한국어 ELI5 문서를 만듭니다. 배경, 바뀐 점, 작동 방식, 확인한 증거, 한계와 다음 행동을 전문 용어부터 풀어 설명합니다. 금융 프로젝트도 투자·퀀트 전문가가 아니라는 기준으로 씁니다.

왜 했나
무엇이 바뀌나
어떻게 확인했나
어디까지 믿나
5

나중에도 찾을 수 있게

문서는 기본적으로 프로젝트의 outputs/ 안에 넣고 Git 기록에 함께 남깁니다. 원격 저장소가 연결돼 있고 이번 작업에서 올리기가 허용된 경우에는 원격에도 포함합니다. 아직 원격이 없거나 올릴 권한이 없으면, 없는데 있다고 말하지 않고 상태를 분명히 알립니다. 완료 채팅에는 항상 클릭 가능한 파일 링크를 제공합니다.

지금 적용된 상태 전역 규칙은 ~/.codex/AGENTS.md에 저장했습니다. 이 대화에서도 즉시 따르며, 새 Codex 작업은 해당 전역 지침을 읽어 같은 기준으로 시작합니다.

한 줄 요약: 작업은 가장 강한 검토로 확인하고, 결과는 누구나 이해할 문서로 남긴다.
