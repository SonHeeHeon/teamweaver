03모델은 무엇이고, 솔버는 무엇인가

모델 = 선택 규칙

무엇을 좋은 배치라고 할지, 무엇을 지켜야 할지 방정식으로 적은 것입니다. 요리의 조리법에 해당합니다.

솔버 = 계산하는 도구

그 방정식을 풀어 조합을 찾는 프로그램입니다. 같은 조리법을 실행하는 다른 조리 도구에 해당합니다.

이번 솔버 실험은 같은 입력과 같은 방정식을 CBC·HiGHS·SCIP에 주고, 제한 시간 안에 유효한 답과 품질 근거를 남기는지를 비교했습니다. 서로 다른 방정식의 점수를 비교하지 않았습니다. 다만 방정식 자체를 바꾸면 좋은 배치의 정의가 바뀌므로 다시 검증해야 합니다.

기술 점수 S: 요구에 얼마나 가까운가

각 요구 기술에서 보유 레벨 / 요구 레벨을 계산하고 최대 1로 자릅니다. 사용자가 정한 1~5 가중치로 평균냅니다. 예를 들어 Java 요구 4·보유 3이면 0.75, SQL 요구 3·보유 5면 1입니다. 두 기술의 가중치가 같으면 S는 0.875입니다.

협업 점수 C: 무엇을 가정했는가

C = 0.4 × min(함께 일한 개월 / 12, 1) + 0.6 × 리뷰 점수입니다. 리뷰 점수는 긍정·부정 체크 항목 수의 균형과 텍스트 극성을 반씩 섞고, 있는 방향의 리뷰들을 평균냅니다. 현재는 “소통” 항목 내용에 별도 가중치를 주는 방식이 아니라 체크 개수로 점수를 냅니다.

오래 협업한 쌍에는 긍정적 경험 점수가 붙으면서, 6개월 이상이면 반복 조합 감점도 붙습니다. 익숙한 팀의 안정성과 새 조합의 기회를 함께 보려는 설계 의도입니다. 이 이중 효과가 현실에서 적절한지는 아직 검증하지 않았습니다. 이른바 Clique Penalty는 실제 고차원 집단을 모두 분석하는 장치보다 오래 함께 일한 두 사람의 반복 배치 감점에 가깝습니다.

검증된 현재 배치 점수를 L, 솔버가 제공하는 최고 가능 점수의 상한을 U라고 합니다. gap = max(0, U-L) / max(1, |U|, |L|)입니다. L=-100, U=-90이면 10%입니다. 상한이 없으면 BOUND_UNKNOWN이고, 임의로 추정해 채우지 않습니다.

QUALITY_PASS는 독립 검증 통과·기한 내 저장·gap≤5%입니다. PROVEN_OPTIMAL은 더 강한 조건입니다. CBC는 이번 연결에서 신뢰할 수 있는 U를 제공하지 않아 “PuLP Optimal” 문자열만으로 품질을 확정하지 않았습니다. 작은 문제는 별도 정답 대조 21/21을 통과했습니다.

5%는 pair 절삭이 적용된 현행 목적함수 기준입니다. 절삭 전 모델·고객 만족·기술 충족률의 5% 보장을 뜻하지 않습니다.

대안 생성에서 “다르다”와 “95%”는 어떻게 해석하나요?

이전 후보의 사람/프로젝트 쌍 중 최대 80%까지만 다시 선택하도록 추가 제약을 넣고 반복 풀이합니다. 실제 구현은 이전 집합과의 겹침 상한이며, Jaccard 유사도 자체를 목적함수로 최적화하는 것은 아닙니다.

대안 품질은 alt ≥ A − 0.05 × |A|로 검사해 음수 점수에서도 부호가 뒤집히지 않게 합니다. 이 기준은 A안과의 비교입니다. A안이 진짜 전역 최적이라는 독립 증명이 없으면 대안의 실제 최적값 대비 95% 보장도 없습니다. 조건을 충족한 대안이 3개보다 적을 수 있습니다.

현실 자료 없이 만드는 가상 성과의 올바른 역할

데이터 연결과 평가 계산이 작동하는지 확인할 수 있습니다. 예를 들어 고객 점수·교체·후속 과제를 서로 다르게 생성하고 누락·지연·난도 교란을 넣어 모델이 엉뚱한 지름길을 배우는지 시험할 수 있습니다. 결과 이름에는 SYNTHETIC_TEST_ONLY를 붙이고 현실 효과의 결론을 내리지 않습니다.

현실 결과 접근이 계속 불가능하다면 서비스는 가용률·예산·합의한 선호를 계산해 의사결정을 돕는 도구로 제공할 수 있습니다. “성과가 가장 좋은 팀을 예측한다”는 약속은 범위에서 빼야 합니다. HR팀이 자기 환경에서 평가를 실행하고 승인된 집계만 전달하는 방식은 향후 협의 가능한 대안입니다. 접근 권한이나 협의가 이미 있다고 가정하지 않습니다.

18용어 사전과 지금 준비할 것

PoC / 시제품
아이디어가 동작하는지 보여주는 구현. 운영에 필요한 권한·배포·실데이터 검증까지 모두 끝났다는 뜻은 아닙니다.
MILP
정수 선택과 연속량을 함께 계산하는 최적화. “넣을까 0/1”과 “몇 % 투입할까”를 함께 정합니다.
제약 / 목적함수
제약은 예산 같은 지켜야 할 선, 목적함수는 그 선 안에서 더 좋은 답을 고르는 점수표입니다.
LP relaxation / 완화 문제
0/1 선택을 0~1 중간값도 허용해 더 쉽게 풀어 얻는 상한. 현실에서 그대로 실행할 수 없는 분수 선택이 들어갈 수 있습니다.
incumbent / 현재 유효 후보
지금까지 찾은 실행 가능한 정수 배치. 존재한다고 최적임이 증명된 것은 아닙니다.
bound / gap
아직 가능할 수 있는 최고 점수의 상한과 현재 후보의 차이. 같은 방정식 기준의 계산 품질입니다.
oracle / 소형 정답기
작은 입력의 모든 선택을 조사해 제품 계산 결과와 비교하는 별도 계산 절차입니다.
pair pruning / 관계 쌍 절삭
모든 두 사람 관계를 다 계산하면 커지므로 일부 시너지 쌍만 남깁니다. 모델 자체가 달라질 수 있어 손실을 확인해야 합니다.
RAG / XAI
관련 근거를 먼저 검색해 설명에 넣는 방식 / 왜 그런 판단인지 이해할 수 있게 보여주는 기능. 설명이 그럴듯하다고 효과가 입증된 것은 아닙니다.
SSE
서버가 한 번의 응답을 열어 두고 A안·B안처럼 결과가 나올 때마다 보내는 통신 방식입니다.
fixture / seed / hash
고정 테스트 자료 / 가상 생성의 난수 시작값 / 파일이 같은지 확인하는 지문입니다.
p50 / p95 / 생존 편향
중앙값 / 관측 시간의 95%가 그 아래인 값 / 실패한 느린 실행을 빼고 성공만 보면 빨라 보이는 왜곡입니다.
FTE
전일제 한 사람의 투입량을 1로 보는 단위. 인원수 2명과 각 20%인 총 0.4 FTE는 다릅니다.
shadow mode
실제 결정은 기존 방식으로 하고 추천만 뒤에서 기록해 차이를 점검하는 단계입니다.
